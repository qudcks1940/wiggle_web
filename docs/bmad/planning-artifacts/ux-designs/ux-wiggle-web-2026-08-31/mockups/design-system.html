A · 시스템

추출한 것

도화지가 초록 위에 얹힌 한 장의 종이로 읽힌다. 초록에는 낙서를 넣지 않았다 — 여기서 초록의 역할은 장식이 아니라 여백을 지우는 것.

여기서 지킨 규칙 세 가지. ① 도화지 위·주변에 낙서 0개. ② 도구는 필드 색 안에 반투명으로 눌러 앉혀 그림보다 뒤로 보냄. ③ 도구 선택 상태는 색이 아니라 흰 배경 + 노랑 링 + "선택" 글자 세 겹으로 표시.

그리미는 아이가 불렀을 때만 나온다. 추측을 확신으로 말하지 않고, 한 번에 하나만 묻는다. 선택된 칩은 색만으로 표시하지 않는다 — 노랑 채움 + 안쪽 흰 링 + 체크 아이콘. 캐릭터 자리는 지금 플레이스홀더다. 실제 이미지는 AI로 생성하며 아이 사진은 어떤 경우에도 쓰지 않는다.

C · 적용 — 교사 화면

같은 가족, 다른 말투

색은 같은 팔레트를 쓰되 채도를 뺀다. 초록은 앵커 하나(#2E5F23)와 연한 배지(#E4EFDC)로만 남고, 낙서는 0개, 모서리는 6~10px, 본문은 16px 아래로 내려가고, 그림자는 없다. 아이 화면과 나란히 두면 즉시 다른 대상용으로 읽혀야 한다.

D · 정직한 평가

이 시스템이 풀지 못한 것

초록 필드는 "그리기 화면"을 풀었지 "전체"를 풀지 않았다

도화지 하나를 크게 보여줄 때는 확실히 작동한다. 그러나 동화책 쪽 띠처럼 작은 흰 썸네일을 여러 개 늘어놓을 때는 초록 위에 흰 조각이 흩뿌려져 소란스러워진다. 그래서 B2는 초록이 아니라 연한 지면(#F2F5EE) 위에 두고 1px 테두리 + 단단한 그림자로 분리했다. 즉 액자 전략은 단일 그림 전용이며, 목록에는 별도 규칙이 필요하다.

아이가 초록·노랑으로 그리면 배경과 충돌한다

크레용 팔레트에 초록(#3C772E)과 노랑(#F6C84B)이 UI 색과 같은 값으로 들어 있다. 아이가 화면 가득 초록을 칠하면 도화지와 필드가 섞인다. 지금은 도화지에 0 10px 0 짙은 그림자를 줘서 버티지만, 확실한 해법은 크레용 색을 UI 색에서 완전히 분리하는 것이고 아직 하지 않았다.

한국어 900 무게가 항상 나오지 않는다

Pretendard가 없는 환경(윈도우 크롬, 일부 안드로이드 태블릿)에서 맑은 고딕은 Bold(700) 한 단계뿐이라 900과 800이 같아 보인다. 그래서 위계를 무게에만 걸지 않고 크기·자간·행간에 이중으로 걸었지만, ref-04의 육중한 헤딩 느낌은 그 환경에서 재현되지 않는다. 해결하려면 웹폰트를 실어야 하고 그건 공용 태블릿의 첫 로딩 비용이다 — 미결정.

그리미 캐릭터는 아직 존재하지 않는다

B4의 자리는 플레이스홀더다. AI로 생성할 예정인데, 회차마다 같은 캐릭터로 보이게 하는 일관성이 가장 큰 미해결 위험이다. 표정·각도가 회차마다 바뀌면 아이는 다른 캐릭터로 인식한다. 완화책으로 얼굴 정면 1종만 쓰고 말풍선으로 감정을 표현하도록 설계했으나, 시스템이 아니라 회피다.

낙서가 아이 그림과 경쟁할 위험

A4에 "도화지 주변 40px 금지, 화면당 최대 3개" 규칙을 넣었지만 이건 사람이 지켜야 하는 규칙이고 코드가 강제하지 못한다. 구현 단계에서 낙서를 배경 레이어 컴포넌트 하나로 묶어 화면당 개수를 하드 제한하는 편이 안전하다.

레퍼런스에 없어서 내가 지어낸 것

ref-04에는 도구 스트립, 캔버스, 빈 상태, 교사용 목록, 대화 UI가 하나도 없다. 랜딩 페이지이기 때문이다. 그래서 B3의 도구 스트립, "아직 안 그린 쪽"의 점선 처리, 교사 행의 저채도 규칙, 버튼의 눌리는 두께(0 3px 0)는 전부 추출이 아니라 추론이다. 색·형태·타이포는 ref-04에서 왔지만 인터랙션 패턴은 오지 않았다.

ref-03에서 가져오지 못한 것

사용자가 좋아한 것은 ref-03의 캐릭터가 화면을 가득 채우는 에너지다. 이 문서에는 캐릭터가 실물로 없어서 그 에너지가 없다. 지금 페이지가 ref-04보다 조용해 보인다면 원인은 팔레트가 아니라 주인공 캐릭터의 부재다. 캐릭터 아트가 들어오기 전에는 이 시스템의 최종 온도를 판정할 수 없다.
