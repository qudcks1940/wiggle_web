# Claude 전달용 — 내 번호 입력 / 큰 숫자 키패드

## 확정한 시안과 범위

사용자는 2026-09-09에 번호 입력 화면 **2번**을 선택하고 필요한 에셋을 요청했다.
정본은 `reference/selected-option-2.png`다. 초록 미술실, 왼쪽 오리 몽그리, 오른쪽 큰 스프링 스케치북과 숫자 키패드 구성을 따른다.

이 패키지는 에셋·디자인 전달 자료다. 앱 구현이나 배포는 수행하지 않았다. 앞서 선택한 ‘준비 중 화면 3번’과 서로 다른 화면이다.

## 파일 사용법

- `assets/number-keypad-scene.webp`: 넓은 화면용 완성 배경. 오리, 책상, 크레용, 빈 스케치북이 이미 들어 있다. 글자·로고·숫자·입력창·버튼은 모두 제거했다.
- `assets/number-keypad-scene-1280.webp`: 같은 장면의 가벼운 축소본.
- `assets/mongri-keypad-ivory.webp`, `-640.webp`: 좁은 화면용 오리와 크레용 일러스트. **불투명 크림 배경과 책상이 포함**되어 있다. 투명 이미지처럼 겹치지 않는다.
- `assets/*.png`: 편집·보관용 원본. 서비스에는 WebP 사용을 권장한다.
- `tokens.css`: 이 화면에만 적용할 제안 색상. 전역 테마를 덮어쓰지 않는다.
- `manifest.json`: 크기, 파일 용량, 알파 채널 여부와 SHA-256.
- `prompts.json`, `PROVENANCE.md`: 내장 ImageGen 생성 프롬프트와 출처.

전체 배경과 독립 오리를 동시에 표시하면 오리가 두 마리가 된다. 둘 중 화면에 맞는 구성을 선택한다. 오리의 양손과 몸은 한 이미지로 유지한다.

## HTML/CSS로 만들어야 하는 요소

시안 전체를 이미지 버튼이나 이미지맵으로 만들지 않는다. 글자와 조작부는 아래처럼 실제 요소로 구현한다.

| 요소 | 내용 |
|---|---|
| 로고 | 기존 `Logo` 컴포넌트 재사용. 생성 시안 속 로고는 재사용 금지 |
| 듣기 | 기존 `SpeakButton`과 확정 음성 문장 유지 |
| 왼쪽 제목 | 내 번호를 눌러요 |
| 왼쪽 설명 | 우리 반에서 내 번호를 골라 주세요. |
| 나무 간판 | 실제 서버 학급명. ‘우리 반’은 시안 예시 |
| 입력 라벨 | 내 번호 |
| 입력 값 | 실제 학생 입력과 별도 ‘번’ 접미사. 시안의 12는 예시이며 초기값은 빈 값 |
| 키패드 | 1 2 3 / 4 5 6 / 7 8 9 / 빈 자리 0 지우기 |
| 주 버튼 | 들어가기 / 요청 중에는 기존 확인 중… |
| 보조 링크 | 수업 코드 다시 입력하기 |

키패드의 빈 자리는 버튼으로 만들지 않고 레이아웃 공백으로 둔다. 삭제 아이콘은 기존 벡터 방식으로 구현하고 `지우기` 라벨을 같이 표시한다. 키패드 키·번호 표시창·노란 버튼의 테두리, 배경, 그림자는 CSS로 만든다. 별도 숫자 PNG는 필요하지 않다.

## 기존 기능 연결

작업 시작 시 최신 `app/components/JoinClient.tsx`를 확인한다. 이번 대상은 `mode === "seat"` 분기다.

- 수업 코드 4자리 입력과 다른 **명단의 자기 번호** 입력 화면이다. 번호 범위는 기존 계약의 1~99, 최대 두 자리다.
- 키패드 탭과 물리 키보드 입력은 동일한 `seatInput` 상태를 갱신한다. 0도 두 번째 숫자로 쓸 수 있어야 한다.
- `지우기`는 마지막 한 자리만 지운다. 예: 12 → 1 → 빈 값. 잘못된 입력을 고치면 기존 오류를 해제한다.
- 숫자 두 자리를 눌렀다고 자동 제출하지 않는다. 명시적인 `들어가기` 또는 폼 Enter로 기존 `checkSeat()`를 실행한다.
- 각 숫자·삭제 키는 `type="button"`, 입장 버튼만 `type="submit"`을 쓴다.
- 초기 빈 값에서 입장 비활성, 요청 중 중복 제출 방지, 0/없는 번호/연결 오류 안내를 유지한다. 실제 동작은 기존 서버 검증을 따른다.
- 입력값이 바뀌지 않은 채 화면에만 숫자가 보이는 일이 없도록 표시·상태·제출 값을 일치시킨다.
- 기존 `seatStatus` 응답에 따라 최초 사용자는 프로필 만들기, 기존 사용자는 그림 비밀번호 확인으로 간다. 인증이나 API 계약을 바꾸지 않는다.
- 학생 명단·실명·최근 학생 목록을 표시하지 않는다. `NO_ROSTER` 준비 화면과 잘못된 수업 코드 화면은 그대로 유지한다.
- 기존 음성 정본: `선생님이 알려 준 내 번호를 눌러요. 다 눌렀으면 들어가기를 눌러요.`

## 넓은 화면 배치

기준 장면은 **1690×931**이다. 아래는 시안을 읽은 배치 시작값이며 브라우저 검증 수치가 아니다. 전체 비율을 유지하는 장면 안에 HTML을 올리고 최종 배치에서 직접 조정한다.

| 영역 | x | y | 폭 | 높이 |
|---|---:|---:|---:|---:|
| 로고 | 40 | 30 | 250 | 76 |
| 음성 | 1476 | 36 | 182 | 66 |
| 제목 | 105 | 152 | 615 | 100 |
| 설명 | 164 | 276 | 540 | 48 |
| 학급명 간판 | 1006 | 98 | 174 | 58 |
| 번호 라벨 | 1000 | 170 | 190 | 40 |
| 번호 표시창 | 870 | 215 | 448 | 110 |
| 키패드 전체 | 823 | 341 | 543 | 379 |
| 노란 입장 버튼 | 797 | 739 | 587 | 76 |
| 코드 재입력 | 968 | 826 | 280 | 44 |

키패드는 3열, 열 간격 약 18px, 행 간격 약 12px로 시작한다. 각 키는 기준 장면에서 약 168×86px. 오류가 생기면 키패드/버튼과 겹치지 않는 별도 영역을 확보하고 콘텐츠 높이를 늘린다.

배경에 무조건 `cover`를 쓰면 노트와 조작부 위치가 어긋난다. 노트 내부로 HTML이 들어오는지 확인한다. 긴 학급명을 과하게 축소하지 말고 간판 아래의 HTML 영역으로 확장하거나 줄바꿈한다.

## 태블릿·휴대전화 구현 제안

좁은 화면은 별도 사용자 승인 시안이 아닌 구현 제안이다. 데스크톱 전체를 작게 줄여 터치 크기를 잃지 않는다.

- 세로 태블릿·휴대전화·높이가 짧은 가로 화면에서는 크림 배경의 문서 흐름으로 바꾼다.
- 로고/음성 → 제목과 작은 오리 일러스트 → 학급명/번호 → 키패드 → 입장/코드 링크 순서로 구성한다.
- 독립 오리는 160~240px 너비로 시작하고, 화면 높이가 짧으면 장식 그림을 줄여 키패드 공간을 확보한다.
- 키패드는 3열을 유지하고 키 높이는 56px 이상을 권장한다. 모든 조작부는 최소 44×44px, 본문 16px 이상.
- 불필요한 자동 초점으로 OS 키보드를 먼저 열지 않는다. 화면 키패드와 물리 키보드를 모두 지원한다. 읽기 전용 입력으로 고정해 보조 기술 사용자의 직접 입력을 막지 않는다.
- 최소 높이만 줄여 억지로 한 화면에 맞추지 않는다. 필요하면 세로 스크롤을 허용하고 CTA가 접근 가능한지 확인한다.
- 입력은 연결된 label과 오류 설명을 갖고, 장식 배경은 `alt=""` 또는 CSS 배경으로 둔다. 포커스 표시를 없애지 않는다.

## 구현 후 확인할 동작

1. 1 → 2 입력 시 12 표시, 지우기 시 1, 다시 지우면 빈 값. 9 → 9는 99, 세 번째 숫자는 기존 두 자리 제한을 따른다.
2. 화면 키패드와 물리 키보드로 입력한 값 모두 같은 번호로 제출되는지 확인한다.
3. 0/빈 값/없는 번호/네트워크 오류, 요청 중 연속 탭, 수정 후 재시도를 확인한다.
4. 최초 번호와 기존 번호가 각각 기존 프로필 생성·비밀번호 분기로 가는지 확인한다.
5. `320×568`, `390×844`, `844×390`, `768×1024`, `1024×768`, `1440×900`에서 잘림·가로 넘침·키 크기·탭 초점·오류 메시지 겹침을 실측한다.
