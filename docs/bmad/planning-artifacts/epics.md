# Wiggle Web - Epic Breakdown

## Overview

이 문서는 **현장 검증 최소본**의 에픽·스토리 분해다.

목표는 아크 기능 전체 완성이 아니라, **학교와 지역아동센터 두 곳에 실제로 들어가
PRD §8의 `M-1`(교사가 두 번째 회차를 스스로 진행했는가)을 측정하는 것**이다.

신규 요구사항 17개를 전부 만들지 않는다. `M-1` 측정에 필요한 것만 만들고,
나머지는 검증 결과를 보고 정한다. 검증되지 않은 커리큘럼 위에 기능을 쌓는 것이
이 프로젝트가 이미 한 번 저지른 실수다.

**UX 설계가 없다.** `bmad-ux`를 아직 돌리지 않았으므로 화면 표현이 필요한 항목은
`[UX 미정]`으로 표시한다. 구현 시점에 정하거나 그전에 `bmad-ux`를 돌린다.

### Additional Requirements

아키텍처 스파인(AD-1~AD-19)에서 나온, 구현을 구속하는 기술 요구사항.

**스키마·데이터 (AD-2)**
- 신규 테이블·컬럼은 `db/runtime.ts`의 `schemaStatements`와 `db/schema.ts` **양쪽에** 등록한다.
- **`classrooms`에 컬럼을 더하려면 `provisionSchema()`에 PRAGMA 확인 + 조건부 `ALTER` 분기를 새로 만들어야 한다.** 없으면 로컬·테스트는 통과하고 운영만 `no such column`으로 500이 난다.
- 새 컬럼은 항상 안전한 기본값을 갖는다. 파괴적 변경 금지.

**동시성 (AD-3)**
- `expectedRevision` CAS + `meta.changes` 검사. **조건부 INSERT에도 적용**한다.
- 경합에서 진 요청은 409를 내지 않고 기존 행을 이어 쓴다.
- 한 batch가 두 애그리게이트를 쓰지 않는다.

**저장소 (AD-6)**
- **채택된 완성 이미지 키를 저장 경로에서 삭제하지 않는다.** 삭제하면 `storybook_assets.object_key`가 가리키는 객체가 사라진다.

**팀 경계 (AD-10·AD-11) — 이번 작업의 가장 중요한 제약**
- **책·쪽 테이블은 책 팀이 소유한다. 아크 팀은 만들지도 읽지도 않는다.**
- 아크 팀이 제공하는 계약은 `artworks.arc_id` + `artworks.episode_id` + `final_image_key` **뿐**이다.
- `(student_id, arc_id, episode_id)`에 완성 작품은 **최대 하나**여야 한다(DB 제약).
  없으면 책 팀이 어느 그림을 쪽에 걸지 스스로 판단하게 되고 두 팀의 답이 갈린다.
- 귀속을 시각·순서로 추론하는 조회를 **어느 팀도** 만들지 않는다.
- ⚠️ 가장 취약한 지점: **완성 이미지 키를 저장 경로에서 삭제하면 책 팀의 쪽이 백지가 된다**(AD-6).
  두 팀이 각자 테스트하면 잡히지 않는다.

**아크 구조 (AD-8·AD-9)**
- 아크 콘텐츠는 `lib/`의 코드 상수. DB에는 아크 id와 콘텐츠 버전만.
- 회차는 순서 index가 아니라 **안정적인 `episodeId`** 로 가리킨다. 버전을 올릴 때 기존 id를 재사용·삭제하지 않는다.
- 회차 상수 읽기는 **언제나 그 아이 책의 `arcVersion`으로** 한다.
- 학급 포인터는 `classrooms`의 신규 컬럼 `current_arc_id` + `current_episode_id`. **`current_activity` 키 문법을 확장하지 않는다** — `normalizeActivityKey`의 조용한 폴백이 모르는 키를 삼킨다.
- 아이의 작업은 `(student_id, arc_id, episode_id)`로 식별된다. **책·쪽 행은 만들지 않는다**(책 팀).
- 교사가 아크를 바꿔도 이전 작품은 그대로 남는다 — 귀속이 작품 행에 고정돼 있어 **아무것도 안 하는 것으로 보존이 성립**한다.
- 회차 귀속은 **작품 생성 시점에 `artworks.arc_id`+`episode_id`로 고정**. 요청 시점 학급 포인터로 재결정하지 않는다.

**접속 맥락 (AD-14)**
- 판별 신호는 `current_episode_id` 유효성 **하나**. `admission_open`·`active`·`teacher_views`·시간대는 근거가 아니다.
- **기본값은 교실.** 교사가 아무것도 누르지 않아도 흐름이 막히지 않는다.
- 요청당 한 번 계산하고 응답 안에서 재사용한다.

**응답 형상 (AD-15·AD-18)**
- 빈 쪽은 `artworkId: null`로만 표현. `completedCount`·`missingCount`·`progressRate`·`completionRate` 류 **집계 필드를 응답 타입에 정의하지 않는다.** 서버는 정렬 키를 주지 않는다.
- 새 이벤트 테이블을 만들지 않는다. 순위·달성률·이탈률 환산 필드를 스키마에 두지 않는다.

**수명 (AD-17)**
- 학급이 내려가면 그 학급 아이는 자기 책·쪽·그림을 열 수 없다. 학급 상태를 우회하는 경로를 만들지 않는다.

**운영 봉투 (AD-19)**
- **FR-15의 `LESSONS` 제거와 아크 콘텐츠 투입은 같은 배포 단위다.** 먼저 지우면 운영에 활동이 0이 된다.
- 회귀 테스트 최소 3건: 아크 CAS 경합 / 지연 flush의 회차 귀속 / 교사 응답 스키마에 집계 필드 없음.

**저장소 관례 (CLAUDE.md)**
- 기능마다 `claude/<짧은-작업명>` 브랜치.
- 최소 검증 통과: `typecheck` · `lint` · `test` · `git diff --check`.
- 모바일 UI는 `320×568`·`390×844`·`844×390`에서 실제 브라우저 확인(`check:browser`).
- **소스 문자열·CSS 정규식 검사만으로 UX 통과를 주장하지 않는다.**
- `main` push는 사용자만 실행한다.

**환경 제약 (이번 워크트리)**
- `package.json`은 `node >= 22.13.0`을 요구하는데 현재 머신은 **Node 20.19.4**다.
  `npm test`(`ERR_UNKNOWN_FILE_EXTENSION ".ts"`, 100 pass/32 fail)와
  `npm run check:browser`(`WebSocket is not defined`)가 **돌지 않는다.**
  검증 스토리는 Node 22 이상을 선행 조건으로 명시해야 한다.

**현장 투입 전 운영 잔여 (current-state.md)**
- 검증용 학생 3명(검증화가·업로드탐색·헤더탐색)이 운영 교사 화면에 남아 있다.
- 인쇄물 QR이 은퇴한 옛 주소로 인쇄돼 있어 재출력이 필요하다.

**구글 OAuth 게시 — 선행 블로커 (2026-08-30 공식 문서 확인)**

게시 전에는 콘솔에 수동 등록한 테스트 사용자만 로그인된다(상한 100명).
교사 로그인이 안 되면 학급 생성이 막히고, 그러면 수업 코드·QR·아크 지정·회차 진행이
전부 막힌다. **`M-1` 측정이 구조적으로 불가능하다.**

- **심사는 없다.** `openid`·`email`·`profile`은 콘솔이 `Non-sensitive`로 자동 분류하며,
  비민감 스코프만 쓰는 앱은 검증 절차가 의무가 아니다. `Publish app` 즉시 반영, 수 분.
  (몇 주 걸리는 심사는 Gmail·Drive 같은 민감·제한 스코프 이야기다.)
- 콘솔 UI가 바뀌었다 — `OAuth consent screen`이 **Google Auth Platform** 섹션으로 분리됐고
  게시 상태는 **Audience**, 스코프는 **Data Access** 페이지에 있다.
- 게시 전 필수 입력: 앱 이름, 사용자 지원 이메일, 개발자 연락처 이메일.
  외부 프로덕션 앱은 정책상 **홈페이지·개인정보처리방침·서비스 약관 URL**도 필요하다.
- ⚠️ **아동 정책**: 구글 API 정책은 "아동이 주 대상인 앱은 Google Sign-In을 쓰지 말 것"과
  "혼합 대상은 구글 계정 없이 앱 전체를 쓸 수 있어야 함"을 요구한다.
  현재 구조(학생은 익명 입장, 구글 로그인은 성인 교사 전용)가 정확히 그 형태다.
  **개인정보처리방침에 이 사실을 명시**해 두는 것이 방어책이며,
  **학생 쪽에 구글 로그인을 붙이는 것은 정책 위반**이다.
- ⚠️ 학교 Workspace 관리자가 서드파티 앱을 차단할 수 있고 만 18세 미만 지정 사용자는 기본 차단이다.
  **게시해도 풀리지 않으며 그 학교 관리자만 해결할 수 있다.** 교사 안내에 대안(개인 Gmail)을 넣는다.
- ⚠️ 2025-06부터 **6개월 미사용 OAuth 클라이언트는 자동 삭제**된다. 방학이 있는 교육용 앱에 실제 위험.
- ⚠️ 2025-06부터 **클라이언트 시크릿이 마스킹**된다(생성 직후 1회만 조회 가능).
  `GOOGLE_CLIENT_SECRET` 백업이 없으면 분실 시 클라이언트를 새로 만들고 리디렉션 URI를 재등록해야 한다.
- `wiggleweb.vercel.app`은 도메인이 사용자 소유가 아니라 Search Console 소유 확인이 안 될 수 있다.
  그 경우 동의 화면에 앱 이름 대신 도메인이 표시된다. **로그인 동작에는 영향이 없다.**

### Story 1.1: 개인정보처리방침과 서비스 약관 페이지

As a **교사**,
I want **이 서비스가 아이 데이터를 어떻게 다루는지 로그인 전에 확인할 수 있기를**,
So that **학교와 보호자에게 안전하다고 설명할 수 있다**.

구글은 외부 프로덕션 앱에 홈페이지·개인정보처리방침·서비스 약관 URL을 요구한다(정책).
동시에 이 문서는 기관 설득 자료이기도 하다.

**Acceptance Criteria:**

**Given** 로그인하지 않은 방문자가
**When** `/privacy`와 `/terms`에 접속하면
**Then** 두 페이지가 인증 없이 열리고
**And** 랜딩(`/`)에서 두 페이지로 가는 링크가 보인다

**Given** 개인정보처리방침을
**When** 읽으면
**Then** 다음이 명시되어 있다
**And** 학생은 이메일·실명·학교명을 제공하지 않고 익명 ID로만 참여한다
**And** 점수·순위·재능 진단을 만들지 않는다
**And** **구글 로그인은 만 18세 이상 교사 계정 인증에만 사용하며 학생은 구글 계정을 쓰지 않는다**
**And** 작품과 이미지의 보관 위치(Turso·Cloudflare R2)와 비공개 원칙
**And** 문의·삭제 요청을 받을 연락처

**Given** 페이지 문구가
**When** 검토되면
**Then** 초등학생 보호자가 읽을 수 있는 평이한 한국어이고
**And** **법률 자문이 아니라 초안이며 사용자 검토가 필요하다는 것을 작업 결과에 명시한다**

**Given** 모바일 뷰포트에서
**When** `320×568`·`390×844`·`844×390`으로 열면
**Then** 가로 넘침 없이 읽을 수 있다

### Story 1.2: 구글 Auth Platform 설정과 앱 게시 (사용자 작업)

As a **제품 오너**,
I want **구글 앱을 프로덕션으로 게시하기를**,
So that **등록하지 않은 기관 교사도 스스로 로그인할 수 있다**.

**심사는 없다.** `openid`·`email`·`profile`은 비민감 스코프이며 `Publish app` 즉시 반영된다.
콘솔 UI가 바뀌어 `OAuth consent screen`이 **Google Auth Platform** 섹션으로 분리됐다.

**Acceptance Criteria:**

**Given** Google Auth Platform → **Data Access** 에서
**When** 스코프 목록을 보면
**Then** `openid`·`email`·`profile` 셋뿐이고 모두 `Non-sensitive` 섹션에 있다
**And** 민감·제한 스코프가 하나도 없다

**Given** **Branding** 페이지에서
**When** 필수 항목을 채우면
**Then** 앱 이름·사용자 지원 이메일·개발자 연락처 이메일이 입력되고
**And** 홈페이지 `https://wiggleweb.vercel.app`
**And** 개인정보처리방침 `https://wiggleweb.vercel.app/privacy` (Story 1.1)
**And** 서비스 약관 `https://wiggleweb.vercel.app/terms` (Story 1.1)

**Given** **Audience** 페이지에서
**When** `Publish app`을 눌러 게시 상태가 `In production`이 되면
**Then** 테스트 사용자 목록에 없는 구글 계정으로도 `/teacher` 로그인이 성공한다
**And** 실제로 등록되지 않은 계정 하나로 로그인해 확인한다

**Given** 게시 후
**When** 동의 화면을 보면
**Then** `확인되지 않은 앱` 경고 인터스티셜이 뜨지 않는다

**Given** 운영 자격증명 관리에서
**When** `GOOGLE_CLIENT_SECRET` 백업 여부를 확인하면

**And** 2025-06부터 콘솔이 시크릿을 마스킹해 재조회가 불가능하다는 것을 인지한다

### Story 1.3: 학교 계정이 막히는 교사를 위한 로그인 안내

As a **학교 Google Workspace 계정을 쓰는 교사**,
I want **로그인이 막혔을 때 무엇을 해야 하는지 알기를**,
So that **포기하지 않고 수업을 시작할 수 있다**.

Workspace 관리자가 서드파티 앱을 차단할 수 있고 만 18세 미만 지정 사용자는 기본 차단이다.
**앱을 게시해도 풀리지 않으며 그 학교 관리자만 해결할 수 있다.**

**Acceptance Criteria:**

> ⚠️ **배치 주의**: 운영에서는 미인증 교사가 로그인 화면을 **보지 못한다.**
> `app/teacher/page.tsx`가 `requiresHostedTeacherAuthentication()`일 때 즉시
> `/api/auth/google/start`로 redirect하므로, `TeacherApp.tsx`의 `구글로 로그인` 카드는
> **로컬에서만 렌더된다.** 안내를 거기 넣으면 아무도 못 본다.
> 그리고 Workspace 차단은 **구글 화면에서** 일어나며,
> 콜백 실패는 `app/api/auth/google/callback/route.ts`의 `fallback`이 **설명 없이 랜딩으로 버린다.**

**Given** 구글 인증이 실패해 콜백이 되돌아올 때

**Given** 교사가 학급 화면을 열면
**When** 아크 진행이 표시되면
**Then** 아크 이름과 현재 회차가 보이고 다음 회차를 여는 행동이 같은 화면에 있다
   (2.1이 만든 컨트롤을 재사용한다 — 중복 구현하지 않는다) `[UX 미정]`

**Given** 1회차를 빠진 아이가
**When** 2회차 수업에 입장하면
**Then** 교사가 지정한 오늘 회차를 그린다
**And** 빠진 회차를 경고·독촉·미완료 표시로 알리지 않는다

**Given** **새로 추가하는** 응답 필드에
**When** 이름을 붙이면
**Then** `completedCount`·`missingCount`·`progressRate`·`completionRate` 류 집계 필드를 **정의하지 않는다**
**And** 서버가 새 정렬 키를 주지 않는다
**And** ⚠️ 기존 `artworkCount`·`drawingArtworkCount`·`completedArtworkCount`는 **AD-15 이전 자산이며 이번 범위에서 건드리지 않는다**
   (제거하면 `유지` 범위인 FR-31의 교사 화면이 깨진다. 정리는 별도 결정이다)
**And** 이 경계를 검증하는 회귀 테스트가 있다 *(선행: Node ≥ 22.13.0)*

**Given** 교사가 아크를 중간에 바꾸거나 끝내면
**When** 그 행동이 기록되면
**Then** 실패·이탈 신호로 계측하지 않는다
**And** 새 이벤트 테이블을 만들지 않는다

### Story 3.3: 교사가 아크를 바꿔도 아이 작품이 남는다

As a **교사**,
I want **아크를 바꾸거나 중간에 끝내도 아이들이 그린 것이 사라지지 않기를**,
So that **커리큘럼을 현장에 맞게 조정하는 것이 두렵지 않다**.

**Acceptance Criteria:**

**Given** 아이가 아크 A의 회차들을 그린 상태에서
**When** 교사가 학급 아크를 B로 바꾸면
**Then** 아크 A의 작품이 삭제되거나 이동되지 않는다
**And** 귀속이 그대로 유지된다
**And** **아무 추가 동작도 필요하지 않다** — 귀속이 작품 행에 고정돼 보존이 자동으로 성립한다

**Given** 교사가 아크를 바꾼 뒤
**When** 아이가 입장하면
**Then** 아크 B의 오늘 회차를 그리고, 아크 A의 작품은 보관함에서 계속 열린다

**Given** **아크 전환·종료 컨트롤**의 확인 문구가
**When** 표시되면
**Then** `되돌릴 수 없다`고 말하지 않는다 — 되돌릴 수 있는 정상 동작이다
**And** ⚠️ 이 조건은 **아크 컨트롤에만 적용된다.** 학급 삭제 문구는 AD-17에 따라
   되돌릴 수 없다는 것과 아이가 그림을 다시 열 수 없다는 것을 **계속 명시해야 한다** — 부드럽게 바꾸지 않는다

### Story 3.4: 책 팀이 읽을 계약을 고정한다

As a **책 기능을 만드는 다른 팀**,
I want **어떤 그림이 어느 회차의 것인지 명확한 계약으로 받기를**,
So that **각자 판단해 서로 다른 답을 내지 않는다**.

**Acceptance Criteria:**

**Given** `(student_id, arc_id, episode_id)` 조합에
**When** 완성 작품을 조회하면
**Then** 최대 하나임이 DB 제약으로 보장된다
**And** ⚠️ 레거시 행은 `arc_id`·`episode_id`가 NULL이다. SQLite 부분 UNIQUE는 NULL을 서로 다르게 보므로 안전하지만,
   **`IFNULL(arc_id,'')` 같은 정규화를 쓰면 모든 레거시 완성작이 한 슬롯에서 충돌한다** — 쓰지 않는다
**And** 제약 위반이 `db.batch` 안에서 발생하면 **500이 아니라 409 + `code`로 변환한다**

**Given** 🔴 작품 저장 경로의 정리 코드를
**When** 수정하면
**Then** `removeCandidates([...])` 호출에서 **완성 키 항목만 `null`로 바꾼다**
**And** ⚠️ **옛 썸네일 정리는 유지한다** — 같은 호출이 둘을 함께 지우므로 줄 전체를 지우면
   자동저장마다 썸네일이 R2에 누적된다
**And** 지우면 `storybook_assets.object_key`가 가리키는 객체가 사라져 아이가 만든 책 쪽이 영구히 백지가 된다

**Given** 재완성 회귀 테스트는
**When** 작성 가능성을 따지면
**Then** ⚠️ **지금은 작성할 수 없다** — `reopen` 경로가 저장소에 존재하지 않고
   `WHERE ... AND status <> 'complete'` 때문에 두 번째 완성에 도달할 수 없다
**And** 이 사실을 스토리 결과에 기록하고 회귀 테스트는 `reopen` 도입 시로 이연한다
**And** 그때까지 이 삭제는 도달 불가능한 죽은 코드다

**Given** 계약 문서가
**When** `docs/`에 작성되면
**Then** `arc_id`·`episode_id`·`arc_version`·`final_image_key`의 의미와 보장이 적혀 있다
**And** **완성 키를 지우면 책이 깨진다**는 경고가 명시된다 — 두 팀이 각자 테스트하면 잡히지 않는다
**And** 회차 순서는 아크 상수가 정본이며 책 팀이 재정의하지 않는다는 것이 적혀 있다

**Given** 아크 팀의 변경이
**When** 배포되면
**Then** `storybooks`·`storybook_assets` 테이블을 건드리지 않았음이 확인된다
