# Wiggle Web 확정 제품 결정

> 마지막 갱신: 2026-09-09
> 이 문서에는 사용자가 명확히 확정한 결정만 기록한다. 제안·추측·검토 중인 내용은 `pending-decisions.md`에 기록한다.

## 프로젝트와 제품 중심

1. 기존 Flutter 저장소를 수정하지 않고 `wiggle_web`을 별도 Git·GitHub 저장소로 운영한다.
2. (2026-08-23 확정) 이후 웹 개발은 신규 팀 저장소 `https://github.com/wwwiggle/new_wiggle`에서 계속한다. 기존 `yonghwan86/wiggle_web`은 Vercel 연결을 실제로 바꾸기 전까지 현재 운영 배포 원본으로 보존한다.
3. (2026-08-23 확정) 신규 팀 저장소는 `main`을 기본 브랜치로 사용하고, 현재 검증 브랜치 `codex/updated-design-storybook`을 Pull Request로 `main`에 병합한다. 이후 기능도 직접 `main`에 쌓지 않고 기능 브랜치와 PR 흐름을 사용한다.
4. 제품 중심은 `AI 그림 학습 도구 + 교실 창작 코칭 플랫폼`이다.
5. 이야기·가족 공유·구독은 그림 학습과 교사 코칭 이후 단계적으로 확장한다.
6. AI는 그림을 대신 완성하거나 평가하지 않고 아이가 호출했을 때만 돕는다. AI 도우미의 이름은 `몽그리`다(2026-09-07 사용자 결정, 옛 이름 `그리미`). 이름을 바꿔도 안전 필터는 좁히지 않는다 — 저장된 과거 코칭 기록과 모델이 옛 이름을 쓰는 경우를 계속 막아야 하므로 두 이름을 함께 검사한다.
7. 점수·순위·재능 진단·공개 SNS 경쟁은 만들지 않는다.
8. 핵심 학생 대상은 **초등학교 1~5학년**이다(2026-09-09 사용자 결정, 종전 "3학년 이상"을 바꿈). 1학년이 글을 못 읽어도 되도록 그림·아이콘·음성·큰 터치 영역을 함께 제공하고, 안내 문장은 한 문장 20자 안팎의 질문형으로 짧게 쓴다.

## 학생 입장과 기록

1. 수업 코드와 학급 QR은 학급 입장 수단이며 학생 신원이나 작품 접근 권한이 아니다.
2. 작품과 과정 기록은 서버가 발급한 익명 학생 ID에 저장한다.
3. 학생 이메일·학교명 없이 참여한다. 학생 실명은 교사가 만든 학급 명단에만 두고 그 학급 담임 교사에게만 보여 준다(2026-09-07 사용자 결정). 이유: 교사가 15명 남짓한 학급을 직접 열고 명부와 대조하려면 부르는 이름만으로는 부족하다는 현장 의견. 학생 화면·가족 공유·그림책·AI 요청에는 실명을 싣지 않으며, 학급을 지우면 명단도 함께 지운다.
4. 그림 비밀번호는 3개를 사용하며 과거 4개 비밀번호 호환 기능은 제거한다.
5. 동물 선택지와 그림 비밀번호 선택지는 각각 10개를 제공한다.
6. 같은 기기 재접속과 공유 태블릿 학생 전환을 지원한다.
7. 메인 화면의 수업 코드와 학급 QR은 모두 학급을 확인한 뒤 같은 학생 입장 화면으로 이어진다.
8. 기존 학생은 해당 학급 안에서 `동물 + 별명 + 그림 비밀번호 3개`를 입력해 기존 익명 학생 ID와 작품을 연다.
9. 다른 공용 태블릿에서 같은 프로필로 들어가는 것은 예외 복구가 아니라 정상적인 재입장이다.
10. 학급 학생 전체 목록이나 입장 순서 번호를 학생 식별 수단으로 사용하지 않는다.
11. 학생 프로필이 하나도 없는 새 학급은 신규 프로필 생성 화면을 바로 열고, 프로필이 생긴 뒤에는 신규 학생과 기존 학생의 진입 버튼을 함께 보여준다.
12. 신규 학생과 기존 학생을 나누는 두 버튼 문구는 `새로 시작하기`와 `내 그림 이어가기`로 한다.
13. 기존 학생의 기본 재입장 수단은 학급 안의 `동물 + 별명 + 그림 비밀번호 3개`이며, 개인 QR이나 교사 재발급을 기본 복구 방식처럼 학생·교사 화면에 표시하지 않는다.
14. 그림 별명 후보는 동물별로 10개 이상을 제공한다. 후보는 초등학생이 읽기 쉬운 한글 낱말로 만들고 전체 후보가 서로 겹치지 않아야 하며, `다른 별명` 주사위는 현재 별명을 즉시 반복하지 않고 두 후보만 왕복하지 않아야 한다.
15. 별명의 띄어쓰기는 표시용으로만 유지한다. 신규 중복 검사, 동일 자격정보 검사, 기존 학생 재입장, 관련 rate-limit 대상 키에서는 모든 공백 차이를 무시한다(`토끼 화가` = `토끼화가` = 앞뒤·연속 공백 변형). 공백만 무시하고 서로 다른 한글 문자는 합치지 않으며, 기존 DB 프로필도 migration 없이 같은 규칙으로 검색된다.
16. 예외(2026-09-09 사용자 결정): 씨앗 선 커리큘럼의 "친구 그림 보기"를 위해, **같은 학급 안에서 교사가 그 회차를 연 동안만** 반 작품을 이름·번호 없이 그림만 볼 수 있다. 학급 입장 정보만으로 다른 학생 작품을 여는 것은 여전히 불가하고, 작품 소유권·저장 경로는 바뀌지 않는다.

## 학습 과정

> 2026-08-30 개정: 아래 1~4항은 기존 `4단계 기능 훈련 사다리`를 대체한다.
> 교체 이유와 폐기된 결정은 이 절 끝의 「폐기된 결정」에 보존한다.

1. 제품의 교육학적 근거는 다음 세 가지의 조합이다. **`VTS 기반`이라고 표기하지 않는다.**
   - **See-Think-Wonder** (Harvard Project Zero, Visible Thinking) — 관찰·추론·질문을 끌어내는
     발문 루틴. 변형이 허용되고 훈련·라이선스 부담이 없다.
   - **Studio Thinking**의 Reflect / Critique (Harvard Project Zero, Getty 후원) —
     **아이 자기 작품**에 대한 구조화된 발문의 정통 근거.
   - **Storyline Method** (1965, 스코틀랜드 Harkness·Bell·Rendell) — 에피소드를 이어
     하나의 이야기를 여러 회차에 걸쳐 완성하는 구조. 아래 2항의 회차 아크가 이 방법론이다.

   목표는 미술사 지식이나 그림 실력이 아니라 **아이가 스스로 관찰하고 근거를 대는 것**이다.
   기존 그리미 원칙(대신 완성 금지·평가 금지·모르면 추측 금지·한 번에 하나만 질문)은
   이 계열의 진행자 규칙과 같은 것이다. VTS에서 가져오는 것은 세 가지로 한정한다 —
   **근거를 묻는 정신, 환언·가리키기, 정답 없음·정보 미제공 원칙.**

   **VTS 표기를 쓰지 않는 이유** (2026-08-30 조사): VTS는 ①타인의 기성 작품 ②또래 집단 토론
   ③인증 훈련받은 진행자 ④문구·순서 고정을 전제한다. 이 제품은 아이 자기 그림에 1:1로
   AI가 개입하므로 네 가지를 모두 벗어난다. 특히 2번 문항 `무엇을 보고 그렇게 생각했나요?`는
   저자가 없는 이미지용 장치여서, 아이가 저자인 그림에서는 `내가 그렇게 그렸으니까`로
   자명해지거나 자기 그림을 변호하라는 추궁이 된다. Gaufberg et al. 2026(The Clinical Teacher)은
   문구 변경·미훈련 진행자에 의한 진행을 충실도 위반으로 명시 비판한다.
2. **학습의 결과물 단위는 그림 1장이 아니라 회차가 누적된 동화책 1권이다.**
   각 수업은 독립 활동이 아니라 하나의 이야기로 이어지는 한 장면이다. 예시 5회차 아크:
   - 1회차: 동그라미에서 출발해 자전거를 그린다
   - 2회차: 그 자전거가 달리는 장면을 그린다
   - 3회차: 친구들과 함께 자전거를 타는 장면을 그린다
   - 4회차: 자전거를 타고 집에 가는 장면을 그린다
   - 5회차: 집에 도착해 부모님과 함께 자전거를 청소하는 장면을 그린다
   - → 다섯 회차가 모여 동화책 한 권이 된다
3. **출발점은 발산(divergence)이다.** 동그라미 하나처럼 열린 자극을 주고
   아이마다 서로 다른 결과가 나오는 것을 정상으로 본다. 정해진 그림을 따라 그려
   같은 결과에 수렴시키는 활동을 학습의 중심에 두지 않는다.
   발산의 폭은 학급을 이해하는 관찰 지표이지 아이를 매기는 점수가 아니다
   (점수·순위·재능 진단 금지 원칙은 그대로 유지된다).
4. AI는 아이의 생각과 상상을 그림으로 표현하고 확장하도록 돕는다.
   이 역할은 대신 완성하거나 평가하지 않는다는 기존 한계 안에서만 수행한다.
   그리미의 개입 방식은 **회차 안의 단계에 따라 두 가지를 나누어 쓴다.**
   - **그리는 중 — `확장 협업자`**: 아이가 말하거나 끄적이면 그리미가 그것을 받아
     다음을 제안한다. 아이의 발화·표시가 먼저이고 그리미는 뒤따른다.
     근거: StoryDrawer(CHI 2022), 만 6–10세 대상 검증.
   - **마무리할 때 — `틀리는 해석자`**: 그리미가 먼저 해석을 내놓되 **틀릴 수 있는 상태로**
     제시하고 아이가 고치게 한다(`어? 난 이게 우산처럼 보이는데?` → `아니야, 자전거 바퀴야`).
     아이를 추궁하지 않으면서 근거 발화를 끌어내기 위한 설계다.
     근거: Weng et al. 2025(BMC Medical Education).
   두 방식 모두 그리미가 그림을 대신 완성하거나 잘잘못을 평가하지 않는다는 한계를 지킨다.
   그리미는 아이가 호출했을 때만 개입한다는 원칙도 그대로다.
5. 점선 가이드는 아이 그림과 분리된 레이어이며 숨기거나 거절할 수 있어야 한다.
6. 정지된 점선만 보여주지 않고 `짧은 연필 시범 → 점선 연습 → 독립 그리기`로 안내한다.
7. 점선 따라 그리기는 아이가 안내 요소를 그리는 순서에 의존하지 않아야 한다.
   (5~7항의 점선·시범은 아이가 요청했을 때 쓰는 보조 수단으로 유지하며,
   학습 흐름의 기본 골격에서는 내린다.)

8. **회차 아크는 제품에 내장하고 교사는 고르기만 한다.** 교사가 5회차 시나리오를
   직접 짜야 하면 준비 부담 때문에 두 번째 회차부터 쓰이지 않는다. 완성된 아크를
   제품이 제공하고 교사의 수업 준비는 `아크를 하나 고른다`로 끝나야 한다.
   아크 제작은 제품 팀의 일이다. (2026-08-30)
8-1. **다만 아크의 진행은 교사가 자유롭게 정한다.** (2026-08-30)
   - 제품이 제공하는 아크 중 **몇 개를 할지, 어떤 순서로 할지** 제한하지 않는다.
   - **한 아크의 회차 수를 5로 고정하지 않는다.** 아크마다 다를 수 있고,
     교사가 도중에 마무리하거나 더 이어가는 것도 정상 흐름이다.
   - 한 아크가 끝난 뒤 다음 아크로 자동으로 넘어가지 않는다. 넘어갈지는 교사가 정한다.
   - **교사가 아크를 바꾸거나 도중에 마치는 것은 이탈이 아니라 정상 사용이다.**
     이를 실패 신호로 계측하지 않는다.
   - 교사가 아크를 직접 만드는 편집기는 이번 범위에 넣지 않는다(8항 유지).
9. **아이의 아크 진행은 날짜가 아니라 회차 단위이며, 빠진 회차는 빈 쪽으로 남는다.**
   결석한 아이의 동화책은 해당 쪽이 비어 있는 상태로 유지되고 나중에 언제든 채울 수 있다.
   빠진 회차를 건너뛰고 완성 처리하지 않으며, 결석 때문에 아이가 결손감을 느끼게 하지 않는다.
   동화책은 빈 쪽이 있는 상태로도 계속 열람·이어작업이 가능해야 한다. (2026-08-30)
10. 오늘 그릴 장면은 **태블릿이 아이에게 알려준다.** 아이가 매번 고르거나 교사가
   구두로만 지시하는 방식이 아니다. 따라서 제품은 학생별 아크 진행 상태를 보유하며,
   교사의 회차 지정은 기존 `오늘 활동 선택`을 통해 이루어진다. (2026-08-30)
11. 아이는 이전 회차 그림을 **참조용으로 확인**할 수 있다. 지난 그림을 나란히 놓고
   이어 그리는 방식이 아니라 회차마다 새로 그리며, 지난 그림은 볼 수 있으면 된다.
   따라서 `5회차 = 그림 5장 = 동화책 5쪽`이다. (2026-08-30)
12. 교사는 태블릿 전체 확인·태블릿 조언·앞에서 진행·돌아다니며 오프라인 조언을
   상황에 따라 병행한다. 따라서 **교사가 태블릿 앞에 있지 않아도 수업이 굴러가야 하며**,
   교사 진행실은 상시 주시가 아니라 간헐적 확인에 맞춘다. (2026-08-30)
13. **반 진도와 개인 진도가 어긋나면 반 진도가 이긴다.** 결석했던 아이도 오늘은
   반과 같은 회차를 그리고, 빠진 회차는 빈 쪽으로 남는다. 수업이 하나로 굴러가는 것과
   교사 진행의 단순함을 이야기 순서보다 우선한다. (2026-08-30)
14. **그리미의 역할 전환은 아이가 `다 그렸다`고 할 때 일어난다.** 그리는 중에는
   확장 협업자, 완료를 누른 뒤에는 틀리는 해석자다. 그리미가 스스로 때를 판단해
   끼어들지 않으므로 `아이가 호출했을 때만 개입한다`는 원칙이 유지된다. (2026-08-30)
15. **동화책 완성의 보상은 `아이가 제품 안에서 책으로 넘겨보는 것`이다.**
   인쇄·PDF 내보내기·가족 비공개 공유·자동 다음 아크 시작은 이번 범위에 넣지 않는다.
   가족 공유와 구독은 기존 결정대로 후속 단계로 유지한다. (2026-08-30)
16. **구현된 활동 30개(`lib/lesson-content.ts`)는 테스트 진행용이므로 제거한다.**
   실제 커리큘럼 자산이 아니다. 제거는 아크 콘텐츠 준비와 같은 변경에서 함께 한다. (2026-08-30)
17. **그림책 편집기의 `main` 반영은 그림책 편집기 구현 작업을 진행할 때 함께 한다.**
   별도 배포 결정으로 분리하지 않는다. (2026-08-30)
18. **빈 쪽은 아이가 집에서 채운다.** 수업 시간은 반이 함께 진행하는 오늘 회차에 쓰고,
   빠진 회차는 집에서 숙제처럼 채운다. 따라서 접속 위치에 따라 보이는 회차가 다르다. (2026-08-30)
   - **교실에서 들어오면** 교사가 지정한 오늘 회차를 그린다(반 진도 우선, 13항).
   - **집에서 들어오면** 자기 동화책의 빈 쪽을 채운다(개인 진도).
   - 집에서 하는 것은 선택이며 **하지 않아도 불이익이 없다.** 미완료를 독촉하거나
     하지 않은 아이를 표시하지 않는다. 점수·순위·평가를 만들지 않는다는 원칙이 그대로 적용된다.
   - 집 접속도 기존 재입장 방식(`학급 + 동물 + 별명 + 그림 비밀번호 3개`)을 그대로 쓴다.
     별도의 가정용 계정이나 부모 계정을 만들지 않는다.
19. **학급을 삭제하면 그 학급 아이는 자기 그림과 동화책을 더 이상 열 수 없다.** (2026-08-30)
   - 학급 삭제는 되돌릴 수 없다. 교사 화면에 학급 복원 수단을 두지 않는다.
   - 아크를 바꿀 때의 동화책 보존(2항 계열)과는 다른 사건이다.
     아크 전환에서는 이전 책이 남고 열리지만, 학급 폐기에서는 접근이 함께 끝난다.
   - 삭제 확인 문구는 되돌릴 수 없다는 것과 아이가 자기 그림·동화책을 다시 열 수 없다는 것을
     숨기지 않는다. `내부 데이터는 복구를 위해 안전하게 보관됩니다` 같은 문구는 쓰지 않는다.
   - 학생 개별 삭제(`archiveStudent`)는 다르다 — 복원 수단이 있으므로 복원 가능하다고 안내한다.
20. **AI가 생성한 문장은 음성으로 내보내지 않는다.** (2026-08-31)
   음성은 제품에 확정된 시나리오 문장 전용이다(7항의 연장). 그리미 말풍선은 텍스트로만 표시한다.
   비문해 아이의 그리미 참여는 답 칩의 이모지와 장면 삽화가 담당한다.
21. **회차 콘텐츠에 장면 삽화를 포함한다.** (2026-08-31)
   회차 형상은 `{episodeId, title, sceneText, sceneImage}`다. 글·음성·그림 세 채널로
   비문해 아이에게도 오늘 장면이 전달된다. 삽화는 캐릭터와 같은 AI 생성 파이프라인으로 제작한다.

### 폐기된 결정 (2026-08-30)

다음 두 항목은 사용자의 명시적 결정으로 교체됐다. 이력 보존용으로만 남긴다.

- (폐기) 학습 흐름은 4단계다 — 1단계 선·도형 기초 10개 / 2단계 따라 그리기 10개 /
  3단계 관찰 그리기 10개 / 4단계 자유 창작.
- (폐기) 별도의 `바로 자유롭게 그리기` 메뉴는 두지 않고 자유 창작은 4단계에서 제공한다.

**교체 이유:** 기존 4단계는 기능 훈련 사다리였고, 각 수업이 하나의 이야기로 이어져
동화책이라는 결과물이 된다는 제품의 실제 구상이 어느 문서에도 기록된 적이 없었다.
`따라 그리기 10개`는 발산 출발점과 방향이 반대이고, `자유 창작은 4단계에서만`은
1회차부터 창작하는 이야기 아크와 충돌한다.

**구현된 활동 30개(`lib/lesson-content.ts`)는 테스트 진행용 임시 콘텐츠이므로 제거한다**
(2026-08-30 사용자 확인). 아크 안의 워밍업으로 흡수하지 않는다.
단, 제거 시점은 아크 콘텐츠가 준비된 뒤이거나 같은 변경 안이어야 한다 —
먼저 지우면 운영 제품에 아이가 할 활동이 하나도 남지 않는다.
22. 커리큘럼은 기존 30개 레슨을 기준으로 삼지 않고 **씨앗 이야기** 방식으로 짠다(2026-09-09 사용자 결정, 같은 날 12회 독립 씨앗 초안을 이 구조로 바꿈). 계획 정본은 `docs/curriculum-seed-plan.md`다.
   - 씨앗 선은 **첫 회차 한 번뿐**이고, 2회차부터는 아이 자신의 지난 그림이 다음 회차의 씨앗이다(동그라미 → 피자 → 피자 먹는 사람 → …).
   - 씨앗별로 5회차 아크를 3~4개 내장한다. 회차 수는 5로 두되 교사가 언제든 멈추거나 더 연다(8-1항).
   - 2회차부터의 안내는 힌트가 있는 문장이다(1~2학년이 덜 막히도록).
   - 아크가 끝나면 동화책 한 권이 된다(2항). 한 회차의 리듬은 씨앗(또는 지난 그림) 받기 → 그리기 → 이야기 한 줄 → 친구 그림 보기로 고정한다.
23. 반 친구 그림을 보고 하는 토론은 **교실에서 말로** 한다. 앱은 그림만 크게 띄운다(2026-09-09 사용자 결정). 앱 안 댓글·스티커·투표는 만들지 않는다.
24. 씨앗 이야기는 **아크 4개(`circle-story`·`curve-story`·`zigzag-story`·`cross-story`, 각 5회차)로 제품에 내장**한다(2026-09-09). 아크 모델(8항)은 그대로이고 회차에 선택 항목 셋을 더한다: 씨앗 선(`seed`, 1회차에만, 작품 생성 시 지울 수 있는 획으로 심음), 힌트 안내 문장(`prompts`, 아이 화면), 교실 토론 질문(`discussion`, 교사 화면 전용). 교사는 조종석에서 아크를 고르고 회차를 열기만 한다.

## 캔버스와 입력

1. 패드 사용을 중심으로 펜 입력 모드를 기본값으로 한다.
2. 손가락 그리기는 사용자가 명시적으로 선택할 때만 활성화한다.
3. 펜 모드에서 손바닥과 일반 터치는 그림을 방해하지 않아야 한다.
4. 두 손가락 제스처는 확대·축소와 화면 맞춤에 사용한다.
5. 모두 지우기는 확인 후 한 번에 지우며 한 번의 되돌리기로 복원할 수 있어야 한다.
6. 지우개는 실제 지워지는 범위를 네모 커서로 보여준다.
7. 색상은 갈색·민트색을 포함해 충분히 제공하고 선택한 색의 이름을 표시한다.
8. 선 굵기는 현재 선택된 펜을 다시 누르면 그 펜 왼쪽에 펼쳐지는 드래그 슬라이더로 조절한다(2026-08-30 사용자 변경 결정, 2026-09-07 시안으로 확인). 화면 바깥·다른 도구·Esc로 닫는다. 이유: Freeform식의 좁은 세로 플로팅 도구 레일과 넓은 도화지를 유지하면서 굵기를 바꾸기 위해서다. 이 슬라이더는 떠 있는 레일을 쓰는 넓은 화면(가로 900px·세로 600px 이상)에만 둔다. 휴대전화와 세로가 짧은 화면은 2026-08-18의 5단 점 버튼을 그대로 쓴다 — 좁은 화면에서는 팝오버가 도화지를 가리고 44px 터치 목표를 깨기 때문이다. 점은 현재 선택한 색으로 칠하고 지우개 선택 시에는 잉크색으로 남긴다.
9. 도화지는 화면을 가득 채운다(2026-09-07 사용자 결정). 새 작품은 첫 획을 긋기 전까지 그릴 수 있는 넓이의 비율을 따라가고, 한 획이라도 그으면 그 비율로 굳는다 — 그린 뒤에 비율을 바꾸면 이미 그린 선이 늘어난다. 이유: 그리기 화면 시안의 넓은 도화지를 그대로 쓰기 위해서다. 비율은 문서에 함께 저장하며, 세로 값이 없는 기존 작품은 예전처럼 정사각(1024×1024)으로 남는다 — 좌표가 x·y 모두 0~1로 정규화돼 있어 비율을 바꾸면 이미 저장한 아이 그림이 찌그러지기 때문이다. 점선·시범 안내 좌표는 정사각 기준으로 그려 둔 것이라 도화지 가운데의 정사각 영역 안에 넣어 동그라미가 타원이 되지 않게 한다.

1. 학생 홈(2026-08-31 개정): **수업이 열려 있으면 오늘 회차 카드가 홈을 차지**하고

   - 재생은 한국어 음성을 우선 선택하고, 아이가 알아듣기 어려울 정도로 인위적으로 느리게 만들지 않는다.

13. 학생 홈 상단의 선생님 말씀 버튼은 💌 아이콘을 쓴다. 넓은 화면에서는 `💌 선생님 말씀`처럼 글자 라벨을 함께 보여주고(헤더의 아이콘+글자 버튼 규약), 휴대전화 폭에서는 44px 정사각 아이콘 버튼으로 접는다. 👩‍🏫 이모지는 버튼 아이콘으로 쓰지 않는다 — Windows에서 조합 이모지가 깨져 보이고 버튼의 용도가 읽히지 않는다(2026-08-18 사용자 결정). 말풍선·이력 안의 말하는 주체 표시로는 계속 쓴다.
14. 학생 홈 하단 선반 카드는 시안대로 아이콘·제목·상태 칩을 칸 중앙의 한 덩어리로 배치하고, `활동 고르기` 카드에는 상태 칩을 붙이지 않는다.
15. 앱의 기본 색은 파란색이 아니라 초록색이다(2026-09-07 사용자 결정, 2026-09-09 최신 main에 적용). 화면·버튼·배경 그림의 파란 계열은 초록·크림 팔레트로 맞추고, 브랜드 로고·앱 아이콘·오리 몽그리의 파란 모자·스카프와 그리기 팔레트의 물감 색은 바꾸지 않는다.
16. `/join`의 수업 확인 대기·실패 화면은 `docs/design-assets/entry-green/reference/approved-green-palette-fixed.png` 교실 시안을 따른다. 넓은 화면은 팔레트를 잡은 오리 완성 장면을 배경으로 쓰고 문구·버튼은 HTML로 올리며, 좁은 화면은 크림 배경과 독립 오리로 바꾼다. 도움 버튼 문구는 기존 `선생님 불러요`를 유지한다.

## 그림책 만들기

1. 외부 Canva 편집 화면을 붙이지 않고 Wiggle 안에서 직접 동작하는 그림책 편집기를 사용한다(2026-08-20 사용자 결정).
2. 각 쪽의 이야기 글은 하나만 두며 페이지 위쪽 가운데의 고정 영역에서만 편집한다. 글 요소를 추가·복제·이동·회전하는 기능은 제공하지 않는다(2026-08-21 사용자 결정). 이유: 초등학생이 글 배치를 따로 조정하지 않고 이야기 작성에 집중하게 한다.
3. 학생의 완성 그림과 새 그림은 글 아래의 지정된 그림 영역 안에서만 추가·이동·크기 변경·회전할 수 있다. 그림과 선택 박스는 같은 종횡비를 유지하고 지정 영역 밖으로 나갈 수 없다(2026-08-21 사용자 결정). 원본 이미지의 흰색·투명 빈 캔버스는 선택 박스에 포함하지 않고 실제로 보이는 그림의 픽셀 경계에 맞춘다. 원본 자산은 보존하고 요소별 내용 경계를 저장하며, 자동 계산과 `빈 여백 없이 맞추기`를 함께 제공한다(2026-08-23 사용자 결정).
4. 사용자가 올린 배경 이미지는 페이지 전체를 채우는 배경층이 되며, 그 위에 고정 이야기 글과 그림이 올라간다. 배경색은 이미지가 없거나 투명한 부분의 바탕으로 유지한다(2026-08-21 사용자 결정).
5. 그림책은 가로·세로·정사각형 세 가지 비율을 제공한다. 새 그림책을 만드는 모든 진입 경로에서는 편집기를 열기 전에 세 모양 중 하나를 먼저 고르고, 편집 중에도 비율을 바꿀 수 있다(2026-08-21·2026-08-23 사용자 결정).
6. 그림의 이동·크기 변경·회전·스냅 상호작용은 MIT 라이선스의 `react-moveable`을 사용하고 라이선스 고지를 저장소에 둔다. 그림책 문서와 이미지 소유권·저장은 Wiggle의 학생 세션, Turso, R2 경계를 그대로 따른다.
7. 편집기는 페이지 추가·복제·순서 이동, 그림 앞뒤 순서·잠금·투명도, 실행 취소·다시 실행, 캐릭터 배경 오리기, 미리보기와 저장을 제공한다.
8. 학생 홈의 확정된 3개 큰 메뉴 순서는 유지하며, 그림책 작업실은 그 아래의 별도 그림책형 카드와 완성 작품 상세의 `이 그림으로 그림책 만들기` 행동으로 진입한다.
9. 그림책 목록·진입·편집 화면은 **책 팀 소유**다(2026-08-31 범위 명시).
   기존 `종이·나무·하늘색 디자인 계승` 문구는 책 팀이 새 DESIGN.md 채택 여부와 함께 재검토한다 —
   아크 팀의 DESIGN.md가 이 영역을 일방적으로 구속하지 않되, 하늘색 1차색은
   새 시스템의 `파랑 1차색 금지`와 충돌함을 책 팀에 전달한다.
10. 학생이 그림책에서 `완성하기`를 누르면 그 학급의 교사는 완성 그림책 목록에서 동물·별명, 완성 시각, 쪽 수를 확인하고 책 전체를 넘겨 보거나 브라우저 인쇄의 `PDF로 저장`을 사용할 수 있어야 한다(2026-08-27 사용자 결정).
11. 교사는 완성 그림책을 체크박스로 여러 권 골라 한 번에 피드백을 요청하거나 한 권씩 요청할 수 있다. 루브릭이 확정되기 전에는 AI 피드백을 임의 생성하지 않고 요청만 `루브릭 대기` 상태로 보존한다(2026-08-27 사용자 결정).

## 교사와 메시지

1. 교사는 전체 학급 또는 특정 학생에게 텍스트 도움말을 보낼 수 있다.
2. 학생은 닫은 교사 메시지를 다시 확인할 수 있어야 한다.
3. 교사가 학생 작품을 보고 있을 때 학생 화면에 이를 알린다.
4. 음성은 후속 단계이며 텍스트를 기본 수단으로 유지한다.
5. 학생을 식별하는 최종 운영 방식은 아직 확정하지 않고, 먼저 교사가 학생 프로필을 확인하는 화면만 만든다.
6. 첫 교사 프로필 확인 화면은 동물, 별명, 생성 시각, 마지막 접속 시각, 전체 작품 수, 진행·완료 작품 수, 현재 진행 상태, 중복 별명 여부를 읽기 전용으로 보여준다.
7. 교사가 학급을 만들 때 명단(번호 + 실명)을 직접 입력하고, 만든 뒤에도 학생을 추가·제거할 수 있다(2026-09-07 사용자 결정, P-001 확정). 학생은 수업 코드나 학급 QR로 들어와 자기 번호를 입력하고 그림 비밀번호로 본인을 확인한 뒤 자기 창을 연다. 명단은 학생 화면에 보여 주지 않는다 — 수업 코드를 아는 사람에게 반 전체 실명이 노출되기 때문이다.
8. (2026-09-07 확정) 자기 등록 입장 흐름 — `새로 시작하기 / 내 그림 이어가기` 갈림길, 별명·동물로 프로필을 찾던 재입장, 중복 프로필 허용(`allowDuplicate`) — 은 **대체가 아니라 제거**다. 명단이 없는 학급에서 아이가 스스로 프로필을 만드는 예비 경로를 남기지 않는다. 이유: 두 경로가 공존하면 같은 아이가 명단 자리와 자기 등록 프로필 둘로 갈라져, 교사 화면의 번호와 실제 작품 주인이 어긋난다. 명단이 아직 없는 학급의 학생 화면은 "아직 준비 중이에요"에서 멈추고 선생님을 부르게 한다(`NO_ROSTER`).
9. 교사 학급 상세는 **오늘 수업 / 작품·그림책 / 명단·설정** 세 탭으로 나눈다(2026-09-09 사용자 선택). 오늘 수업은 현재 회차 학생 그림을 큰 썸네일 격자로 보여 주고 회차 변경·수업 안내·전체 메시지만 상단 행동으로 둔다. 작품 탭은 학생·회차 필터와 완성 그림책 진입을 맡고, 명단 탭은 학생 추가·수정·삭제/복원과 입장 코드·QR·가족 링크·학급 삭제를 맡는다. 이유: 수업 중 확인과 평소 관리 행동이 한 화면에 섞여 있던 복잡도를 줄이기 위해서다.
10. 오늘 수업의 학생 그림은 현재 학급에 열린 회차와 같은 `arcId + episodeId` 작품만 표시한다. 회차가 없을 때만 학생별 최근 작품임을 화면에 명시한다(2026-09-09 사용자 선택을 구현하며 확정). 다른 회차에서 나중에 저장한 그림을 오늘 그림으로 보이면 교사가 현재 수업 상황을 잘못 판단하기 때문이다.

## 배포 원칙

1. 기존 Flutter 저장소에는 변경을 만들지 않는다.
2. (2026-08-18 확정) 배포 체계를 전환한다: 개발은 로컬 폴더 → GitHub push → **Vercel 자동 배포**. ChatGPT Sites와 Codex 독립 검증 게이트는 전환 완료와 함께 은퇴한다. 이유: Sites 프록시 의존(SIWC 헤더 인증)이 이전 불가였고, git push 자동 배포로 반복 속도를 올린다.
3. (2026-08-19 확정) 운영 데이터는 이전하지 않고 **신규 시작**한다. 기존 Sites와 그 데이터는 보존해 가역성을 남기고, 폐기는 사용자 명시 승인이 필요하다. 이유: 실사용 데이터가 소규모(작품 32개)였고 서버가 빈 DB에서 자가 프로비저닝된다.
4. (2026-08-18 확정) 스택은 Next.js + Turso(libSQL) + 기존 R2(S3 API), 교사 인증은 구글 OAuth 자체 구현이다. 호스트 중립 어댑터로 다른 호스팅 이전 시 재공사가 없어야 한다.
5. (2026-08-19 확정) 공개 주소는 무료 서브도메인 `https://wiggleweb.vercel.app`으로 시작한다. 유료 도메인(`wiggleweb.app`)은 실사용이 자리 잡으면 구매를 검토한다.
6. GitHub `main` push(=운영 배포)는 사용자가 직접 실행한다. 에이전트는 기능 브랜치 커밋·push까지만 준비한다.
7. (2026-08-20 확정) Local/Test, Vercel Preview, Production은 사용자가 요청한 같은 기능 코드를 공유한다. 환경별 코드 복사본을 만들지 않고 인증·DB·파일 저장소·시드·비밀값만 중앙 환경 경계에서 선택한다. Local/Test는 원격 운영 자원을 사용할 수 없고, Preview와 Production은 서로 분리된 Vercel 환경 변수와 데이터 자원을 사용한다. 로컬 전용 코드는 `dev-only`, 환경 판별은 `runtime` 디렉터리로 명확히 격리한다. 이유: 로컬 검증 결과를 Preview와 운영에 그대로 승격하면서도 테스트 데이터나 자격증명이 환경 사이에 섞이는 사고를 막기 위해서다.
