# Wiggle 그리기 화면 재설계 조사

조사일: 2026-09-14. 대상: 초등 3–6학년, 읽기가 서툰 아이 포함. 주 기기: 약 1180×820 가로 교실 태블릿. 이번 문서는 방향 비교용이며 제품 결정·코드·배포를 바꾸지 않는다.

## 조사 범위와 해석

공식 도움말·공식 화면 자료의 도구 구성을 비교했다. 아래 상시 행동 수는 기본 화면의 주요 도구 진입점 기준의 대략값으로, 색 하나하나·문서 제목·운영체제 버튼은 제외한다. 버전·화면 폭·선택 도구에 따라 달라진다. 설치 앱에서 터치 영역을 실측한 결과가 아니며, 공개 자료가 밝히지 않은 px 크기는 추정값으로 만들지 않았다.

Apple은 일반 버튼의 최소 히트 영역을 44×44pt로 안내한다. 이는 각 앱이 실제로 준수한다는 증거도, 웹 CSS px와 동일하다는 뜻도 아니다. Wiggle에는 요청 기준인 **주요 행동 최소 56×56 CSS px**, 간격 8px 이상을 설계 목표로 적용한다. 1536px 시안을 1180px로 축소해 비교할 때는 약 73px 이상의 이미지상 버튼이 필요하다. 래스터 목업만으로 실제 히트 영역을 검증할 수는 없다. [Apple 버튼 지침](https://developer.apple.com/design/human-interface-guidelines/buttons)

## 현재 첨부 화면에서 보이는 문제

- 태블릿: 헤더 버튼이 모두 강하게 강조되고, 오른쪽 도구·색 카드가 그림 위를 크게 차지한다. 실제 그릴 종이와 가려지는 부분의 관계가 불분명하다.
- 휴대전화: 도구·굵기·색·입력 모드가 길게 쌓여 그림보다 조작부 비중이 크다. 교사 관찰 안내도 작은 종이의 큰 부분을 덮는다.
- 위 항목은 첨부 화면의 시각 관찰이다. 현재 앱의 실제 터치 영역·스크롤·동작을 테스트했다는 뜻은 아니다.

## Wiggle 설계 원칙

1. **종이가 중심이다.** 도구 자리와 안내 자리를 예측 가능하게 고정하고 그림 핵심을 덮지 않는다. 기존 작품의 비율은 보존한다.
2. **모양 + 짧은 말 + 선택 표시를 함께 쓴다.** 실물 화구, 한글 라벨, 테두리와 체크로 읽기·색 인지 차이를 보완한다.
3. **주요 행동은 56px 이상이다.** 작은 굵기 점도 누르는 칸은 크게 만든다. 실제 1180×820·왼손·오른손으로 검증한다.
4. **자주 쓰는 것은 한 번에, 부가 도구는 한 단계에.** 연필·크레용·마커·수채붓·지우개·되돌리기는 빠르게, 채우기·도형·글씨는 명시적인 더보기 안에 둔다. 숨은 제스처만 요구하지 않는다.
5. **5단 굵기와 16색을 예측 가능하게 유지한다.** 현재 굵기·색을 닫힌 상태에서도 보여주고 상세 색은 무지개 버튼으로 연다.
6. **교사와 몽그리는 역할이 다르다.** 사람 손들기와 AI 도움 버튼을 구분한다. 손들기는 같은 자리에서 `손 내리기`로 바뀌고, 편지는 읽지 않은 수를 유지한다.
7. **교사 안내는 한 번에 하나씩, 저장 충돌은 우선한다.** 관찰은 작은 상태 pill, 표시는 짧은 카드와 두 큰 답 버튼. 충돌 때는 `저장됨`을 동시에 표시하지 않는다. 표시와 안내는 작품 원본에 합성하지 않는다.
8. **휴대전화는 다시 배치한다.** 하단 도구/색 시트를 번갈아 열고 종이를 남긴다. 공유 기기에서는 기본 배치를 복원하며 펜 모드/손가락 모드를 명확히 보여준다.

## 네 가지 시안

### A — 하단 도크

- **콘셉트 한 줄:** 그림 아래의 한 도구 상자에서 화구·굵기·색을 고른다.
- **장점:** 도구를 찾는 위치가 일정하고 교사가 같은 위치를 설명하기 쉽다. 좌우 종이가 열려 있다.
- **위험:** 하단 도크가 종이 높이를 줄이고 손목에 닿는다. 16색과 5단 굵기를 한 줄에 억지로 축소하지 않아야 한다.
- **휴대폰 세로:** 아래에는 현재 화구·지우개·되돌리기·색 버튼을 남긴다. 도구와 색은 하단 시트로 번갈아 열며 제목은 한 줄로 줄인다.

### B — 왼쪽 화구 레일

- **콘셉트 한 줄:** 왼쪽 필통에서 화구를 꺼내고 오른쪽 크레용 상자에서 색을 고른다.
- **장점:** 실물 도구 모양이 명확하고 글을 읽기 전에도 구별하기 쉽다. 도구·색·종이의 경계가 안정적이다.
- **위험:** 양쪽 레일이 그림 폭을 줄인다. 왼손/오른손에 따라 색을 고를 때 그림을 가리므로 좌우 바꾸기와 기본 위치 복원이 필요하다.
- **휴대폰 세로:** 양옆 레일을 없애고 아래 가로 필통으로 바꾼다. 색은 4×4 시트, 교사 표시는 아래에서 올라오는 카드로 옮겨 그림을 남긴다.

### C — 작은 플로팅 패널

- **콘셉트 한 줄:** 평소에는 작은 도구 pill과 색 pill만 띄우고 필요할 때 펼친다.
- **장점:** 네 방향 중 그릴 수 있는 여백을 가장 크게 확보한다. 익숙해진 아이가 한 도구로 오래 그리기 좋다.
- **위험:** 메뉴 속 선생님·편지를 놓칠 수 있다. 메뉴 버튼에 손들기 상태와 안 읽은 수를 유지해야 한다. 기능 목록을 보여 주기 위해 시안은 펼친 상태지만 실제 기본 화면은 닫힘 상태다.
- **휴대폰 세로:** 두 pill을 하단 고정 버튼으로 전환하고 한 번에 한 시트만 연다. 완성은 위에 남기며 메뉴 안의 뒤로·과정·몽그리·선생님·편지는 56px 이상 행으로 제공한다.

### D — 미술 책상

- **콘셉트 한 줄:** 연한 나무 책상 위 종이와 필통·팔레트가 하나의 미술 자리처럼 보인다.
- **장점:** 몽그리의 펠트 질감과 실물 화구가 자연스럽게 연결된다. 종이와 조작부를 직관적으로 구별한다.
- **위험:** 나뭇결·입체감·캐릭터가 그림보다 튀기 쉽다. 장식은 저대비, 버튼은 평평하고 선명하게 만든다. 팔레트 모양에 맞추느라 색 간격을 불규칙하게 만들지 않는다.
- **휴대폰 세로:** 나무 여백을 최소화하고 필통은 하단 시트로, 팔레트는 4×4 색 판으로 바꾼다. 몽그리는 작은 고정 버튼으로 남긴다.

## 공통 기능·상태 계약

모든 안에 뒤로(내 그림), 로고, 작품 제목과 저장 상태, `과정 보기`, `몽그리 부르기`, `선생님`, 💌와 안 읽은 수, `완성`이 있다. C에서는 완료 외 행동을 명시적인 메뉴로 묶는다. `선생님`을 누른 뒤 같은 버튼은 `손 내리기`로 바뀐다. 이는 두 버튼을 동시에 표시하는 기능이 아니다.

도구 계약은 되돌리기·다시하기, 연필·크레용·마커·수채붓·지우개·나비 스티커, 더보기의 채우기·도형·글씨(Aa), 5단 굵기, 16색과 색 더보기, 펜 모드/손가락 모드다. Aa는 사용자 요청의 도구 아이콘 예외이며 다른 영문 UI는 Wiggle 로고뿐이다.

관찰 pill은 A, 선생님 표시 카드는 B, 저장 충돌 배너는 D에서 대표 상태로 보여준다. **세 상태는 네 안 모두 지원하는 공통 상태**이며 동시에 모두 띄우는 화면이 아니다. 충돌 배너는 헤더 바로 아래에 고정하고 저장 상태를 `저장 확인 중`으로 바꾼다. 표시 카드는 최신 하나만 띄우고 `👍 알겠어요` / `🤔 잘 모르겠어요`로 답한다. 닫은 선생님 메시지는 💌에서 다시 읽는다. 어느 것도 저장되는 원본 그림의 일부가 아니다.

D의 충돌 문구 `다른 태블릿에서 바뀐 그림이 있어요.`와 `선생님과 확인`은 비교용 제안 문안이다. 기존 저장 충돌 해결 기능을 제거하거나 덮어쓰기로 단순화하자는 결정이 아니다. 실제 구현에서는 보존·비교·복구 동작에 맞춰 연결해야 한다.

## 생성 방식과 프롬프트 기록

내장 imagegen을 한 장씩 사용했다. 1536×1024 가로 화면, 기기 테두리 없는 앱 목업, 진초록 #184028·크레용 노랑 #f3c94f·크림/흰 종이, 초등 3–6학년, 아이콘 우선 한글 라벨, 56 CSS px에 대응하도록 약 76 이미지 px 버튼을 공통 요청했다. 모든 시안은 같은 노란 집·빨간 지붕·파란 창·갈색 문·오른쪽 초록 나무·노란 해·초록 풀 선을 비교 기준으로 삼는다. 생성 특성상 획 자체가 픽셀 단위로 같다는 뜻은 아니다.

프롬프트 방향: A는 한 하단 도크와 열린 더보기·관찰 pill, B는 왼쪽 실물 화구와 오른쪽 16색 크레용 상자·교사 표시 카드, C는 최소 플로팅 도구/색 pill과 펼친 메뉴, D는 연한 나무 책상·하단 필통·옆 팔레트·모서리 몽그리·저장 충돌. A의 그림을 후속 시안의 시각 참조로 사용한다. D의 몽그리는 첨부 펠트 오리의 파란 베레모·목도리·노란 몸을 기준으로 한다.

이 파일들은 시각 방향 비교용이다. 실제 버튼 히트 영역·포커스·펜/손바닥 처리·메뉴 전환·안내 겹침은 구현 후 기기 검증이 필요하며, 이미지의 선택점·배치만으로 통과를 주장하지 않는다.
